# 票据驱动开发：可复制的起步模板

复制本目录内容到新项目；将`AGENTS.template.md`重命名为`AGENTS.md`。所有`<...>`均需填写，未填写内容不是已经确认的事实。

本目录提供执行与交接模板，产品文档仍由新项目自行编写：

| 文件 | 最小内容 |
|---|---|
| README.md | 简介、环境、启动/验证命令、文档导航 |
| PRD.md | 问题、目标用户/场景、MVP规则、非目标、用户流程、验收标准 |
| TECH_STACK.md | 实际选择、原因、版本、工具链、替代方案 |
| ARCHITECTURE.md | 实际目录/模块、依赖方向、接口、数据模型、关键事务/迁移 |

`docs/`文件随开发更新；`dev/templates/`用于复制成具体票据。已合并票据可移到`dev/done/`并更新链接。`skills/`等重复操作规范按需要建立，不要求一开始就有。

顺序：立项/定范围 → 勘察与风险验证 → 里程碑 → 一张票据审核 → 实施/验证/审查 → 验收/PR → 检查目标分支并合并 → 从main交付 → 更新状态 → 下一票。

先把`docs/Repo_Current_State.md`和T0001勘察票据填好，再开始非简单实施。新会话只需要读取AGENTS、Current_State和目标票据，再按需读取设计/源码。
