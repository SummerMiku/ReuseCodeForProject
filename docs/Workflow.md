# 开发工作流

1. 确定目标用户、场景、MVP成功标准和非目标，写入PRD。
2. 只读勘察实际项目；高风险平台/第三方能力先做小型验证。
3. 选择够用的技术与架构；关键选择记录理由，避免把未来设计当成已实现。
4. 按可独立验收的结果拆里程碑和票据，列出依赖；只批准准备实施的一票。
5. 读取真实基线/源码，记录未知项，在分支或必要的worktree实施。
6. 按阶段运行相关测试；系统行为使用真实环境核对。测试失败时修正计划。
7. 审查完整diff，修复可定位的问题；更新报告和残留风险。
8. 用户验收、提交/推送、创建PR；确认head/base分别是什么。
9. 合并后读取main实际内容；从main构建/部署/安装并核对产物身份和数据保留。
10. 更新状态和后续事项，归档票据；交接后从准确下一步继续。

小修复可以把plan/context/tasks/report合在一份文件；多阶段任务分别保存。审查可由本人、协作者或另一个获授权的AI执行，不要求一定使用多代理。

完成标准：批准的需求已实现，必需检查通过，相关验收有证据，重要审查问题已解决，文档与代码一致，main和交付产物可定位。仍未检查的项目明确列出，不能仅凭合并或构建成功标为全部验收通过。
